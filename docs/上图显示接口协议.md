# 上图显示接口协议

## 1. 适用范围

本文定义 Mission Control 地图中所有“上图显示”能力的后端接口约束。

“上图显示”包括但不限于：

- 普通点位
- 多边形、圆形等正式几何要素
- 手动态势点
- 车辆点
- 融合态势点
- 路网
- 禁行区 / 禁行点
- 路径规划结果

## 2. 开发原则

后续新增任何 `xx 显示` 功能，必须满足以下要求：

1. 必须有后端接口承载数据，不能只在前端临时绘制。
2. 至少要有一个“写入 / 更新接口”和一个“查询接口”。
3. 如果需要实时刷新，必须补充事件接口，例如 SSE。
4. 前端允许存在绘制中的临时预览，但最终显示数据必须以后端返回结果为准。
5. 前端左侧绘图工具、右侧输入表单、外部业务模块，最终都必须落到同一套后端上图接口上，不能各自维护一份前端私有图层数据。

推荐模式：

- 写入 / 更新：`POST`
- 查询：`GET`
- 删除 / 清空：`DELETE`
- 实时刷新：`GET /events`

## 3. 地图基础要素接口

服务：`map_marker_service`

默认地址：`http://localhost:28001`

### 3.1 普通点与正式几何要素

#### 3.1.1 新增点位

- 方法：`POST`
- 路径：`/map/add/point`

请求示例：

```json
{
  "lat": 39.909231,
  "lng": 116.397128,
  "type": "default",
  "label": "测试点"
}
```

说明：

- 用于普通点位上图。
- 左侧地图工具栏绘制点、右侧手动输入点、外部接口上图，都应统一走此接口。

#### 3.1.2 新增多边形

- 方法：`POST`
- 路径：`/map/add/polygon`

请求示例：

```json
{
  "label": "测试多边形",
  "points": [
    { "lat": 39.909231, "lng": 116.397128, "alt": 0.0 },
    { "lat": 39.909800, "lng": 116.398100, "alt": 0.0 },
    { "lat": 39.908900, "lng": 116.398600, "alt": 0.0 }
  ]
}
```

说明：

- 用于正式几何图形上图，不是禁行区接口。
- 左侧多边形 / 矩形绘制默认应走该接口。

#### 3.1.3 新增圆形

- 方法：`POST`
- 路径：`/map/add/circle`

请求示例：

```json
{
  "lat": 39.909231,
  "lng": 116.397128,
  "alt": 0.0,
  "radius_m": 120.0,
  "label": "测试圆形"
}
```

说明：

- 用于正式圆形要素上图。
- 左侧圆形绘制、右侧手动输入圆形，统一走该接口。

#### 3.1.4 查询全部普通点与正式几何

- 方法：`GET`
- 路径：`/map/get/allstuff`

响应说明：

- 返回普通点和正式几何要素的聚合结果。
- 前端基础要素图层应以此接口为主。

#### 3.1.5 查询正式几何

- 方法：`GET`
- 路径：`/map/get/geometries`

说明：

- 仅返回正式几何要素，不含普通点。

#### 3.1.6 查询单个点位

- 方法：`GET`
- 路径：`/map/get/point/{point_index}`

#### 3.1.7 删除单个点位

- 方法：`DELETE`
- 路径：`/map/delete/point/{point_index}`

#### 3.1.8 删除单个正式几何

- 方法：`DELETE`
- 路径：`/map/delete/geometry/{geometry_index}`

#### 3.1.9 清空全部正式几何

- 方法：`DELETE`
- 路径：`/map/delete/geometries`

### 3.2 态势点与车辆点

#### 3.2.1 新增手动态势

- 方法：`POST`
- 路径：`/map/situation/add`

请求示例：

```json
{
  "lat": 39.9132,
  "lng": 116.4178,
  "label": "态势 A",
  "icon": "/rana_icon.png",
  "range_diameter": 600
}
```

#### 3.2.2 查询全部态势

- 方法：`GET`
- 路径：`/map/situation/get/all`

说明：

- 返回手动态势和车辆点的聚合结果。

#### 3.2.3 查询手动态势

- 方法：`GET`
- 路径：`/map/situation/get/manual`

#### 3.2.4 查询车辆点

- 方法：`GET`
- 路径：`/map/situation/get/vehicles`

#### 3.2.5 按名称查询态势

- 方法：`GET`
- 路径：`/map/situation/get/one`

查询参数示例：

```text
?name=态势 A
```

#### 3.2.6 更新车辆点

- 方法：`POST`
- 路径：`/map/vehicle/update`

请求示例：

```json
{
  "timestamp": "2026-03-17 14:25:30.000",
  "vehicle_id": "151231131",
  "longitude": 116.397128,
  "latitude": 39.909231,
  "altitude": 43.5,
  "heading": 180,
  "pitch": 5,
  "roll": -2,
  "speed": 15,
  "offset": 10
}
```

说明：

- 同一 `vehicle_id` 重复上报时按 upsert 更新位置。

#### 3.2.7 查询车辆点聚合结果

- 方法：`GET`
- 路径：`/map/vehicle/get/all`

#### 3.2.8 删除手动态势

- 方法：`DELETE`
- 路径：`/map/situation/delete/{situation_index}`

#### 3.2.9 清空手动态势

- 方法：`DELETE`
- 路径：`/map/situation/clear`

---

### 3.3 路网与禁行区

#### 3.3.1 新增路段

- 方法：`POST`
- 路径：`/map/network/add/edge`

请求示例：

```json
{
  "points": [
    { "lat": 39.909231, "lng": 116.397128 },
    { "lat": 39.909800, "lng": 116.398100 }
  ]
}
```

#### 3.3.2 查询全部路网与禁区

- 方法：`GET`
- 路径：`/map/network/get/all`

响应说明：

- 返回路网折线 `items`
- 返回禁区 `forbidden_items`

#### 3.3.3 替换整套路网

- 方法：`POST`
- 路径：`/map/network/replace`

说明：

- Geoman 编辑 / 橡皮擦删除路网后，前端应将当前剩余路网整体回写到该接口。

#### 3.3.4 清空路网

- 方法：`DELETE`
- 路径：`/map/network/clear`

说明：

- 当前业务里前端通常只做“隐藏路网”，不建议直接清空后端数据。

#### 3.3.5 保存路网

- 方法：`POST`
- 路径：`/map/network/save`

#### 3.3.6 加载路网

- 方法：`POST`
- 路径：`/map/network/load`

说明：

- 用于把后端路网数据重新加载到地图。

#### 3.3.7 查询禁区

- 方法：`GET`
- 路径：`/map/forbidden/get/all`

#### 3.3.8 设置全部禁区

- 方法：`POST`
- 路径：`/map/forbidden/set`

请求示例：

```json
{
  "forbidden": [
    {
      "forbidden_id": 1,
      "kind": "polygon",
      "data": [
        { "lat": 39.909231, "lng": 116.397128 },
        { "lat": 39.909800, "lng": 116.398100 },
        { "lat": 39.908900, "lng": 116.398600 }
      ]
    },
    {
      "forbidden_id": 2,
      "kind": "point",
      "data": { "lat": 39.910000, "lng": 116.399000 }
    }
  ]
}
```

说明：

- 左侧工具栏如果显式进入“绘制禁区”模式，完成绘制后应统一走该接口同步。
- 禁行区 / 禁行点删除后，也必须回写该接口。

---

### 3.4 路径规划显示

#### 3.4.1 路径规划

- 方法：`POST`
- 路径：`/map/route/plan`

请求示例：

```json
{
  "start_type": "point",
  "start_index": 1,
  "end_type": "point",
  "end_index": 8,
  "via_indices": [3, 5]
}
```

响应说明：

- 返回 `shortest_route`
- 返回 `fastest_route`
- 返回 `routes`
- 前端据此上图显示最短路径与最快路径

#### 3.4.2 地图事件流

- 方法：`GET`
- 路径：`/map/events`

说明：

- SSE 事件流
- 地图基础要素、态势、车辆、路网等变化后可通过该接口触发前端刷新

## 4. 融合态势接口

服务：`fusion_situation_service`

默认地址：`http://localhost:28006`

### 4.1 查询融合态势

- 方法：`GET`
- 路径：`/fusion-situations`

响应说明：

- 返回 `items`
- 返回 `count`
- 返回 `updated_at`

### 4.2 接收融合态势并更新显示

- 方法：`POST`
- 路径：`/fusion-situations/ingest`

请求示例：

```json
{
  "timestamp": "2026-03-16 18:02:34",
  "target_count": 2,
  "fused_targets": [
    {
      "time": "2026-03-10 10:00:02",
      "fusion_id": "F-faa958c0",
      "target_type": "装甲车辆",
      "lon": 116.01003,
      "lat": 39.01,
      "alt": 11.2,
      "max_threat": 85.0
    }
  ]
}
```

说明：

- 外部融合结果写入后，前端通过查询接口或事件接口刷新显示。

### 4.3 融合态势事件流

- 方法：`GET`
- 路径：`/fusion-situations/events`

说明：

- SSE 事件流
- 接收到新的融合态势后，服务端推送刷新事件，前端再重新查询 `/fusion-situations`

---

## 5. 前端接入要求

前端实现地图显示时，必须遵守以下规则：

1. 左侧绘图工具完成后，必须调用后端接口入库，再由查询接口回显。
2. 右侧输入框手动上图，必须调用后端接口，不能只在浏览器内生成图层。
3. 实时消息流只负责触发刷新，不应替代查询接口本身。
4. 删除、编辑、清空操作必须同步更新后端，不能只删前端图层。
5. 同一类显示对象必须复用同一套后端接口，不允许再引入前端私有格式。
6. 地图局部操作反馈默认在地图操作模块内显示，不默认进入全局通知中心。
路径规划结果可作为例外同步进入通知中心。

## 6. 后续扩展模板

后续若新增 `无人机显示`、`雷达探测显示`、`告警区域显示` 等功能，至少应补齐：

1. `POST /xxx/add` 或 `POST /xxx/update`
2. `GET /xxx/get/all`
3. `DELETE /xxx/delete/{id}` 或 `POST /xxx/set`
4. 如需实时刷新，再补 `GET /xxx/events`

不允许仅在前端本地绘制后直接当作正式显示结果使用。

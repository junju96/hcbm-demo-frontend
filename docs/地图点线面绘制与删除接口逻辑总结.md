# 地图点线面绘制与删除接口逻辑总结

> 整理日期：2026-08-11
> 范围：行动序列面板的地图上图/清除逻辑（点、线、面）
> 事实来源：`src/features/mission-control/modules/coordination/api/coordinationApi.js`、`panels/right/ActionSequencePanel.vue`、`backend-dev/地图上图显示API接口-0602.md`、`docs/上图显示接口协议.md`

## 1. 总体架构

- 地图服务是独立的 **map_marker_service**（`25.11.1.178:28001`），**前端直连，不经过 28600 后端**。
- 开发环境走 Vite proxy：`/map` → `http://25.11.1.178:28001`（`vite.config.js:11-14`）；生产环境由 `joinMapUrl` 拼 `MAP_SERVICE_BASE_URL`（`serverConfig.js:21`）。
- 前端封装统一返回 `{ ok, error, data }`（`safeFetch`，8 秒超时）。

## 2. 接口清单

| 功能 | 方法与端点 | 请求体 | 封装函数（coordinationApi.js） |
|---|---|---|---|
| 批量添加地图对象（面/圆/点） | POST `/map/object/batch/add` | `{ items: [...] }` | `batchAddMapObjects`（:642） |
| 批量删除地图对象 | POST `/map/object/batch/delete` | `{ unique_ids: [...] }` | `batchDeleteMapObjects`（:657） |
| 批量添加路线临时显示（线） | POST `/map/route/display/batch/add` | `{ items: [...] }` | `batchAddRouteDisplay`（:666） |
| 批量删除路线临时显示 | POST `/map/route/display/batch/delete` | `{ unique_ids: [...] }` | `batchDeleteRouteDisplay`（:695） |
| 添加多边形（单个） | POST `/map/add/polygon` | `{ label, points }` | `addPolygon`（:681） |

语义要点（`地图上图显示API接口-0602.md`）：

- 路线临时显示是**进程内临时状态**，不写正式地图对象集合；batch/add 按 `unique_id` 追加或覆盖；batch/delete 后无剩余时广播 `map_route_cleared`。
- 对象 batch/delete 按 `unique_ids` 批量删除正式对象，返回成功/失败清单。
- `addPolygon` 的 `unique_id` **由地图服务端生成**，前端从响应取回（`data.data.unique_id` 或 `data.unique_id` 两级兼容）。

## 3. 绘制逻辑（drawPlanOnMap，ActionSequencePanel.vue:750-878）

### 3.1 坐标提取与配色

- `extractCoordinates(param)`（:585）：按优先级取 `param.waypoints` → `param.target.location`（侦察多边形）→ 单点字段（`recon_position`/`fire_position`/`target_position`/`position`）；统一输出 `{lon, lat, alt}`，兼容两套键名；(0,0) 与非法点被 `isValidPoint` 过滤。
- 配色：按车辆在 `vehicle_summary` 中的序号从 8 色色轮取色（`getVehicleColor`，:559），路线与对象共用 `color` 字段。
- `unique_id` 命名：`as-{planId}-{vid}-{action_id||action_seq}-{类型后缀}`，各段经 `sanitizeId` 替换特殊字符（:660）。

### 3.2 四类图元的构造与分流

| 图元 | 触发条件 | 走哪个接口 | item 结构 |
|---|---|---|---|
| **线（路线）** | `action_type = auto-move` 且点数 ≥ 2 | `batchAddRouteDisplay` | `{ unique_id: '…-route', points: [{lat,lng,alt}], color }` |
| **面（侦察多边形）** | `action_type = lens-recon` 且点数 ≥ 3 | `addPolygon`（逐个） | `{ label: '{vid} - {action.name}', points: [{lat,lng,alt}] }`，不含 unique_id（服务端生成，前端从响应回收） |
| **面（多边形区域）** | 其他类型且点数 ≥ 3（自动首尾闭合） | `batchAddMapObjects` | `{ unique_id: '…-area', object_type: 'area', object_subtype: 'polygon_area', name, color, geometry: { type: 'Polygon', coordinates: [[[lon,lat,alt],…]] } }`（GeoJSON） |
| **点（圆形区域）** | 点数 = 1 | `batchAddMapObjects` | `{ unique_id: '…-circle', object_type: 'area', object_subtype: 'circle_area', name, color, geometry: { type: 'Point', coordinates: [lon,lat,alt] }, meta: { radius_m: param.radius_m \|\| param.radius \|\| 100 } }` |

注意：代码里有 `buildLineObject`（:662，`object_type: 'line'`/LineString）但**当前未被调用**——线统一走路线临时显示通道。

发送顺序：路线 → 侦察多边形 → area/circle；全部成功提示"地图上图成功: N 个对象"，任一失败提示对应错误。

### 3.3 调用时机

- `selectPlan` 选中/切换方案：先清后画（:1985-2012）
- `refreshDetail` 自动刷新：先对比新旧坐标（`coordinatesEqual`），无变化不重绘，有变化先清后画（:1965-1979）——轮询下的增量重绘
- 删除车辆行动序列后：清除，剩余车辆重绘（:1781）
- 行动参数保存后：清除 + 重绘（:1648）
- 取消选中 / 组件卸载：清除（:2293 / :2497）

## 4. 删除逻辑（clearPlanOnMap，:880-906）

- **unique_id 不重新计算**：绘制时缓存在两个 ref——`currentRouteIds`（路线）和 `currentMapObjectIds`（多边形服务端返回 uid + area/circle 本地 uid 合并）。
- 清除时先 `batchDeleteRouteDisplay(routeIds)`、再 `batchDeleteMapObjects(objIds)`，各自 try/catch 容错，完成后置空缓存。

## 5. 已知风险点

1. `/map/object/batch/add` 的 item schema（`object_type`/`object_subtype`/GeoJSON 含第三维 alt）**只有前端代码这一处事实来源**，无服务端协议文档，建议与地图服务实现方核对。
2. ~~`addPolygon` 的删除依赖服务端在响应中返回 `unique_id`~~（已修复，2026-08-11）：服务端实际把 id 放在 `feature.id`（feature_store.py），前端原先只读 `data.data.unique_id`/`data.unique_id` 导致多边形 id 漏收、无法删除；现解析顺序为 `data.data.feature.id` → `data.feature.id` → `data.data.unique_id` → `data.unique_id`（ActionSequencePanel.vue:841-845）。
3. 坐标单位：`/map/object/*` 与 `/map/route/*` 用 WGS84 度（lat/lng），与行动参数内部的 10⁶ 缩放整数之间的转换在前端构造时完成，若服务端数据形态变化需同步检查 `extractCoordinates`。

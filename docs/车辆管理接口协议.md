## 1. 文档范围

本文档用于说明控车页相关的车辆管理接口协议，当前对应服务：

- 服务名：`vehicle_control_service`
- 默认地址：`http://localhost:28009`

本文档覆盖以下接口：

- `GET /vehicle/info/all`
- `POST /vehicle/connect`
- `POST /vehicle/catalog/batch`
- `POST /check/vehicle/status`
- `GET /health`
- `POST /user/action`
- `POST /user/action/session`
- `POST /user/action/session/heartbeat`
- `POST /user/action/session/close`
- `GET /user/current`

## 2. 配置约定

服务配置文件：

- `backend/services/vehicle_control_service/config/config.ini`
- 兼容回退：`backend/services/vehicle_control_service/config/service.ini`

示例：

```ini
[service]
timeout_seconds = 5
connect_timeout_seconds = 10

[upstream]
ip = 127.0.0.1
port = 19000

[user_action]
long_connection_enabled = 1
heartbeat_interval_seconds = 10
disconnect_timeout_seconds = 30
cleanup_interval_seconds = 5

[vehicle_catalog]
topic = mgmt/fleet/vehicles/update
```

字段说明：

- `timeout_seconds`
  - 车辆列表、用户动作上报等普通请求超时时间，单位秒
- `connect_timeout_seconds`
  - 车辆连接接口等待上游响应的超时时间，单位秒
- `ip`
  - 上游车辆管理服务 IP
- `port`
  - 上游车辆管理服务端口
- `long_connection_enabled`
  - 是否开启登录长连接保活；开启后心跳超时会自动补发 `disconnect`
- `heartbeat_interval_seconds`
  - 前端建议心跳周期，单位秒
- `disconnect_timeout_seconds`
  - 后端判定掉线并上报 `disconnect` 的超时时间，单位秒
- `cleanup_interval_seconds`
  - 后端扫描过期会话的周期，单位秒
- `topic`
  - 车辆名录批量提交发布到 Zenoh 的主题，默认值为 `mgmt/fleet/vehicles/update`

## 3. 数据模型

### 3.1 车辆信息对象

```json
{
  "id": "v01",
  "name": "UGV-1",
  "type": "UGVTYPE1",
  "ip": "192.168.11.1",
  "vmfCode": "10070001",
  "chassis_status": {
    "connected": true,
    "occupied_by": "SEAT_001",
    "user": "operator_zhang"
  },
  "payload_status": {
    "connected": false,
    "occupied_by": "",
    "user": ""
  }
}
```

字段说明：

- `id`：车辆唯一标识
- `name`：车辆名称，控车页主卡片展示字段
- `type`：车辆型号
- `ip`：车辆设备 IP
- `vmfCode`：车辆 VMF 编码
- `chassis_status`：底盘连接状态
- `payload_status`：载荷连接状态

### 3.2 连接响应对象

```json
{
  "result": "ok",
  "desc": "车辆连接成功"
}
```

字段说明：

- `result`
  - `ok`：连接成功
  - `bad`：连接失败
- `desc`
  - 返回给前端弹窗或提示框展示的描述文本

### 3.3 车辆名录对象

```json
{
  "id": "v02",
  "name": "UGV-2",
  "type": "UGVTYPE2",
  "ip": "25.12.2.1",
  "vmfCode": "10070002"
}
```

字段说明：

- `id`：车辆唯一标识，默认按本地模板生成，例如 `v02`
- `name`：车辆名称，默认按本地模板生成，例如 `UGV-2`
- `type`：车辆类型；页面中的 `TP1` 到 `TP4` 会映射到配置文件里的输出类型
- `ip`：车辆网关 IP；默认按本地模板生成，也允许页面生成后手动修改
- `vmfCode`：车辆 VMF 编码

### 3.4 用户动作对象

```json
{
  "action": "login",
  "username": "老李",
  "ip": "xx.xx.xx.xx",
  "permission": 1
}
```

字段说明：

- `action`：操作类型，可选值：`login`、`logout`、`disconnect`
- `username`：用户名
- `ip`：本机 IP；前端可不传，由服务端自动解析并补齐后再上报上游
- `permission`：权限等级

### 3.5 用户动作会话对象

```json
{
  "session_id": "9c494d32d7fc4d21a6507bf0bb78f7d6"
}
```

字段说明：

- `session_id`：长连接会话唯一标识，由 `POST /user/action/session` 返回

## 4. 接口定义

### 4.1 查询全部车辆信息

- 方法：`GET`
- 路径：`/vehicle/info/all`

响应示例：

```json
[
  {
    "id": "v01",
    "name": "UGV-1",
    "type": "UGVTYPE1",
    "ip": "192.168.11.1",
    "vmfCode": "10070001",
    "chassis_status": {
      "connected": true,
      "occupied_by": "SEAT_001",
      "user": "operator_zhang"
    },
    "payload_status": {
      "connected": false,
      "occupied_by": "",
      "user": ""
    }
  }
]
```

### 4.2 发起车辆连接

- 方法：`POST`
- 路径：`/vehicle/connect`

请求体：

```json
{
  "action": "connect",
  "id": "v01",
  "components": ["chassis", "payload"]
}
```

字段说明：

- `action`：当前固定为 `connect`
- `id`：车辆 ID
- `components`：要连接的组件列表，可选值：
  - `chassis`
  - `payload`

响应示例：

```json
{
  "result": "bad",
  "desc": "目标组件暂不可用"
}
```

### 4.3 批量提交车辆名录

- 方法：`POST`
- 路径：`/vehicle/catalog/batch`

请求体：

```json
[
  {
    "id": "v02",
    "name": "UGV-2",
    "type": "UGVTYPE2",
    "ip": "25.12.2.1",
    "vmfCode": "10070002"
  }
]
```

字段说明：

- 请求体为数组，表示当前已配置完成的车辆名录
- 数组长度范围为 `1` 到 `4`
- 页面左侧固定提供 4 个车位，但未生成 JSON 的车位不会提交

响应示例：

```json
{
  "result": "ok",
  "desc": "已发布 1 辆车配置到 mgmt/fleet/vehicles/update",
  "count": 1,
  "topic": "mgmt/fleet/vehicles/update"
}
```

说明：

- `debug = 1` 时，服务会把最近一次提交内容写入 `backend/services/vehicle_control_service/data/vehicle_catalog_last_submit.json`
- 服务会把数组原样发布到 Zenoh 主题 `mgmt/fleet/vehicles/update`
- 若需调整发布主题，可在 `backend/services/vehicle_control_service/config/service.ini` 的 `vehicle_catalog.topic` 中修改

### 4.4 健康检查

- 方法：`GET`
- 路径：`/health`

响应示例：

```json
{
  "status": "ok",
  "debug": true,
  "connect_timeout_seconds": 10,
  "user_action_long_connection_enabled": true,
  "zenoh_connected": true,
  "zenoh_error": ""
}
```

### 4.5 用户操作接口

- 方法：`POST`
- 路径：`/user/action`

请求体：

```json
{
  "action": "login",
  "username": "老李",
  "ip": "xx.xx.xx.xx",
  "permission": 1
}
```

字段说明：

- `action`：操作类型，可选值：`login`、`logout`、`disconnect`
- `username`：用户名
- `ip`：登录 IP；前端不传时由后端自动补齐为本机 IP
- `permission`：权限等级

响应示例：

```json
{
  "result": "ok",
  "ip": "192.168.1.16",
  "long_connection_enabled": true
}
```

### 4.6 创建用户动作长连接会话

- 方法：`POST`
- 路径：`/user/action/session`

请求体：

```json
{
  "username": "老李",
  "permission": 1
}
```

响应示例：

```json
{
  "enabled": true,
  "session_id": "9c494d32d7fc4d21a6507bf0bb78f7d6",
  "heartbeat_interval_seconds": 10,
  "disconnect_timeout_seconds": 30
}
```

说明：

- 当 `long_connection_enabled = 0` 时，返回 `enabled = false`，前端不建立心跳。
- 该接口只建立本服务内部会话，不额外向上游发送 `login`；`login` 仍由 `POST /user/action` 负责。

### 4.7 用户动作长连接心跳

- 方法：`POST`
- 路径：`/user/action/session/heartbeat`

请求体：

```json
{
  "session_id": "9c494d32d7fc4d21a6507bf0bb78f7d6"
}
```

响应示例：

```json
{
  "result": "ok"
}
```

说明：

- 当前端掉线、浏览器异常退出或页面不再发送心跳时，后端会在超时后自动调用上游 `POST /user/action` 并发送 `action = disconnect`。

### 4.8 关闭用户动作长连接会话

- 方法：`POST`
- 路径：`/user/action/session/close`

请求体：

```json
{
  "session_id": "9c494d32d7fc4d21a6507bf0bb78f7d6"
}
```

响应示例：

```json
{
  "result": "ok",
  "closed": true
}
```

说明：

- 显式退出登录时，前端应先调用 `POST /user/action` 上报 `logout`，再调用本接口清理本地会话。

### 4.9 查询当前登录用户

- 方法：`GET`
- 路径：`/user/current`

响应示例（有有效登录态）：

```json
{
  "logged_in": true,
  "username": "老李",
  "permission": 2,
  "ip": "25.11.1.180"
}
```

响应示例（当前无有效登录态）：

```json
{
  "logged_in": false,
  "username": "",
  "permission": null,
  "ip": ""
}
```

说明：

- `login` 成功上报后会更新当前用户状态。
- `logout` 与 `disconnect` 会清空当前用户状态。
- 其它后端服务可直接查询该接口，获取当前有效登录用户和权限等级。

# Demo 测试清单

## 1. 启动

```bash
cd demo/frontend
npm install
npm run dev
```

构建校验：

```bash
cd demo/frontend
npm run build
```

## 2. 路由与页面壳

### 2.1 单屏

打开：

- `/mission-control`

确认：

- 顶部状态栏正常显示
- tab 行正常显示
- 左侧工作区正常显示
- 中间工作区占位正常显示
- 右侧模块主面板正常显示

### 2.2 双屏主屏

打开：

- `/mission-control/main`

确认：

- 顶部只保留主屏需要的控制项
- 左侧工作区正常显示
- 中间工作区占位正常显示
- 右侧为视频 Dock，而不是模块右面板

### 2.3 双屏辅屏

打开：

- `/mission-control/aux`

确认：

- 顶部工具栏正常显示
- 左侧工作区正常显示
- 中间上方任务看板正常显示
- 中间下方模块详情区正常显示
- 右侧 AI Dock 正常显示

## 3. 模块切换

### 3.1 tab 切换

确认：

- `示例模块` 和 `协同模块` 都能切换
- 切换模块后左侧共享面板仍按规则保留

### 3.2 左侧共享面板

确认：

- 地图操作面板可打开
- 车辆面板可打开
- 聊天面板可打开

## 4. 任务看板与详情区

在 `/mission-control/aux` 检查：

- 任务卡片可以显示
- 任务卡片在空间有限时能压缩显示
- 点击任务卡后布局不会撑破页面
- 模块详情区不会出现整块空白占位
- 模块详情区内容不足时不会把页面高度撑长
- 模块详情区内容较多时会内部滚动

## 5. 语义目标与动作

检查方式：

- 点击任务卡
- 点击地图操作按钮
- 点击右侧模块主按钮
- 打开 AI Dock

确认：

- 当前点击上下文能被识别
- “加入对话”能把上下文写入聊天输入框
- 后台结构化命令依赖的 `target_id / action_id` 已经存在

## 6. 通知中心

### 6.1 基础功能

确认：

- `Ctrl + .` 可以打开通知中心
- 右上角通知卡片能显示
- 右侧历史抽屉能打开

### 6.2 跳转能力

如果模块发通知时带了：

- `target_route`
- `target_module`
- `target_panel`
- `target_target_id`
- `command`

确认：

- 点击通知后能跳到目标位置
- 需要时能触发动作
- 需要时能把上下文加入聊天

## 7. 16:9 屏幕适配

至少检查：

- `1920 x 1080`
- `1366 x 768`

确认：

- 不出现整页纵向滚动
- 单屏下左右三栏不失衡
- 主屏下视频 Dock 不把中间工作区挤没
- 辅屏下任务看板、详情区、AI Dock 都能在一个屏幕内完成操作
- 面板内部滚动正常

## 8. 回归重点

- 不要把模块业务逻辑重新写回 `page/`
- 不要把接口 URL 写死在面板组件里
- 不要去掉 `target_id / action_id`
- 不要把通知能力写成组件私有逻辑
- 不要用固定高度把 16:9 屏幕撑坏
